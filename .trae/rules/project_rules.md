# MyBlog 项目协作规则

## 每次修改必须完成的两件事

1. **提交到 git**：一次完整改动对应一个 commit，提交信息必须带类型前缀并用中文说明改了什么，例如 `fix: 修复首屏 LU YU 文字裁切`。
2. **提交前验证**：至少跑通 `npm run build`；涉及视觉改动时在 `npm run preview` 下确认效果。

> 按 2026-11-01 的约定：日常改动**不再要求写入 README 或更新日志**。README 只作为项目说明文档按需维护，不作为改动记录。

## 提交信息规范

第一行格式：`<type>(<scope>): <中文描述>`，`scope` 可省略。

| 前缀 | 用途 |
| --- | --- |
| `feat` | 新增功能、页面、组件、内容模块 |
| `fix` | 修复 bug、样式错位、裁切、报错 |
| `style` | 仅样式 / 排版 / 视觉微调（不改逻辑） |
| `refactor` | 重构，不改变对外行为 |
| `perf` | 性能优化 |
| `docs` | 文档、README、规则文件 |
| `chore` | 构建脚本、依赖、配置、杂项 |

示例：`feat: 新增手记分类筛选`、`fix(preloader): 修复大字顶部裁切`、`docs: 补充更新日志与提交规范`。

规则变更本身也按此格式提交。

## 提交约定

- 只提交源码与文档，`node_modules/`、`dist/` 由 `.gitignore` 排除。
- 提交信息第一行简洁描述改动，必要时在正文中补充原因与验证方式。
- 不要混入与本意无关的格式化或文件改动。
- 推送前先确认本地 commit 信息带前缀；一次性推送同一批相关 commit。
